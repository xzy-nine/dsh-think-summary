# 新模式分析：主模型自产小结 + 插件流内捕获

> 思路：通过提示词让主模型在思考时以特定格式自己输出阶段性小结，插件在
> `llm/stream` 瀑布里捕获这些标记，直接作为分段总结展示（替代/补充
> "外部切段 + 启发式/小模型精炼"）。
> 状态：**已实现**（用户决策：完整实现=注入提示词+捕获；默认关；仅展示补充）。
> 配置：`selfSummary: 'off' | 'prompt'`（默认 'off'）。

## 一、技术可行性（逐环节验证）

| 环节 | 方案 | 可行性 |
|---|---|---|
| 提示词注入 | `ctx.systemPrompt.section({ name, order, text })` —— DSH 自带服务，插件按 order 追加固定段（如 order 200），开关控制注册/卸载 | ✅ 已确认 API |
| 流内捕获 | 现有 `llm/stream` 瀑布已观察全部 `reasoning-delta`，正则匹配标记、累积提取 | ✅ 零新增机制 |
| 展示 | 捕获的小结直接 push 到 state 作为 segment（`kind: 'self'`），dock/tail/思考总结视图直接渲染 | ✅ 复用现有管线 |
| 兜底 | 模型未输出小结时，现有外部切段照常工作（新模式的定位是"优先"，非"替代"） | ✅ 天然兼容 |

## 二、优点

1. **语义边界 + 语义摘要一体**：模型在自己上下文最完整时总结（"读完一个子问题就总结"），
   比事后切段 + 启发式提取更准——直接解决"分段粒度不准/摘要质量"两个痛点。
2. **省精炼 token**：小结即高质量摘要，可跳过小模型精炼（每段省 ~0.85k token）。
3. **零解析成本**：捕获是流内正则，0 token。
4. **实时**：小结随思考流出现立即展示，无需等段切完。

## 三、缺点 / 风险

1. **主模型不可靠（核心风险）**：格式漂移（缺闭合标签/中英混用/嵌套）、忘记输出、
   输出位置随机 → 需要容错解析 + 外部切段兜底。
2. **污染思考 + 额外 token**：
   - 要求模型输出标记是**机械任务**，可能打断自然推理流（对思考深度的影响需实测）；
   - 小结本身是**额外输出**（模型不提示不会写），每个标记 ~50-100 tok；
     若小结密度 ≈ 精炼段密度，净省精炼 0.85k/段 vs 花 ~0.1-0.2k/标记 → **净省**；
     若模型小结过密（每段总结）→ 可能不省甚至更贵。
3. **自总结偏差**：模型对自己思考的即时小结可能漏关键点（缺少独立读者视角的校验）。
4. **只对注入后生效**：旧会话/旁路流无小结（旁路流本就过滤，影响可控）。
5. **格式冲突**：标记可能与代码/正文相似文本冲突 → 选不常见格式 + 解析容错。

## 四、Token 经济账

- 现状：外部切段 0 token + 启发式 0 token + 精炼每段 ~0.85k（若开启）。
- 新模式：主模型多输出 ~0.1-0.2k token/小结（标记+内容），省 0.85k/段精炼。
- 结论：**小结频率 ≤ 精炼段频率时净省**；过密则更贵——需实测密度。

## 五、实现思路（草案 → 已实现）

```
配置：selfSummary: 'off' | 'prompt'（默认 off——提示词有副作用）
Host：
  1. installSelfSummaryPrompt(ctx, getOptions)
     selfSummary='prompt' 时监听 `system-prompt/assemble` waterfall，组装时
     追加 think-summary:self 段（order 200）：
     '在思考过程中，每完成一个重要子问题或得出阶段性结论时，输出一句不超过80字的阶段性小结，格式：【思考小结】内容。除该格式外不要在其他地方使用"思考小结"字样。'
     —— waterfall 事件每次组装都执行，不依赖 systemPrompt 服务注册时机
        （修复：此前 section 注册可能因服务晚挂载而静默失败）
  2. makeSelfSummaryCapture(onSelf)  // llm/stream 瀑布内，每 think 一个
     捕获【思考小结】标记后内容，到 下一个标记 / 行尾 / 句末标点 / 240 字符
     （最先者）为止 → push segment { summary, tokens: 0, kind: 'self' }
     （不经启发式/精炼，直接展示；仅展示补充，不影响外部分段）
  3. 无小结区域仍走现有外部切段（兜底）
客户端：设置卡片加 selfSummary 下拉；小结段显示"思考小结"标签（不显示 token 计数）
```

验证：捕获器单元测试（3 小结正确、不吞后续思考）+ 端到端（stream 路径
kind='self' 段正常入 state）+ waterfall 追加验证通过。

## 六、建议与决策点

- **推荐实现为可选项（默认关）**：提示词会改变模型思考方式，可靠性与 token 经济需实测。
- **先实测再定默认值**：加提示词跑一轮真实长思考，检查：①格式稳定性（命中率）；
  ②小结质量；③小结密度 vs 精炼段数（算 token 账）。
- 实现范围二选一：
  - **A. 仅捕获器**（不加提示词）：用户自行在其他地方注入提示词，插件只捕获展示——零副作用；
  - **B. 完整**（注入提示词 + 捕获器）：开箱即用，但有思考方式副作用。
